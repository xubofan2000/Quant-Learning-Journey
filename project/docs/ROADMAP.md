# Bohr 12 个月就业路线图

## 目标与约束

目标是在不裸辞、保持全职工作的前提下，一年内获得量化相关岗位。长期投入约 12-15 小时/周；按能力门槛推进，不按自然月自动升级。

第一目标依次为量化数据开发 / 金融数据工程、量化研究平台 Python 开发、投研/金融/风险数据支持。中低频量化开发、量化研究助理和后续转向中低频研究属于第二阶段。高频研究、低延迟 C++、顶级私募纯策略和明显依赖高学历/微观结构/Tick 数据的岗位不作为一年主线。

学历、专业、所在城市、可接受城市、薪资下限和通勤/远程约束待确认；岗位清单必须单独核查这些硬门槛。

## 年度时间预算

以下为 52 周的主预算；部分周可同时贡献两个能力域，但复盘时按实际小时归类，避免 Agent 或工程包装侵占研究基础。

| 能力域 | 周数预算 | 占比 | 验收证据 |
| --- | ---: | ---: | --- |
| 数学统计与 Python 基础 | 8 周 | 15% | 独立实现、统计报告、基础题与口述 |
| 金融数据工程与软件工程 | 13 周 | 25% | 数据契约、模块、测试、CI、SQL/Linux/数据库证据 |
| 因子研究、回测和研究方法 | 16 周 | 31% | 因子卡、正式回测、最终 OOS、稳健性和失败复盘 |
| 作品集、面试和求职 | 10 周 | 19% | 可复现项目、简历、面试记录和投递漏斗 |
| Agent/LLM、模拟执行等扩展 | 最多 5 周 | 最多 10% | 有前置门槛的选修；不影响持续投递 |

## 52 周阶段划分

| 周期 | 主线 | 核心产出 | 退出门槛 |
| --- | --- | --- | --- |
| W1-3 | 恢复、统计、Python 工程化 | 能力基线、真实收益统计报告、15-25 个核心测试 | 独立恢复通过；核心模块无导入副作用；CI 运行量化测试 |
| W4-9 | 数据契约、三个因子、因子评价、正式回测、最终 OOS | 主研究项目的完整研究链 | 数据时点正确；成本/现金/无法成交可对账；OOS 只评估一次 |
| W10-12 | 作品集、简历、面试与首轮投递 | 可复现主项目、失败因子、30-50 个定向投递 | 真实反馈进入计划闭环 |
| W13-20 | 数据工程与平台能力深化 | SQL/Linux/数据库、增量 ETL、质量与可观测性 | 能处理数据故障并讲清数据模型 |
| W21-32 | 时间序列、第二因子项目、组合约束与研究平台接口 | 第二次独立复现或跨数据集验证 | 研究结论、工程接口和测试可由他人复现 |
| W33-39 | 求职强化与短板修复 | 面试题库、项目讲解迭代、持续投递 | 根据真实通过率/反馈调整，不追求固定课程覆盖率 |
| W40-42 | Agent/LLM 选修，最多 2-3 周 | 有评估集的单 Agent 辅助工具 | 仅在真实因子通过 OOS 后；量化提升相对确定性基线 |
| W43-47 | 模拟执行与治理选修，4-5 周 | 模拟订单、账本、风控、回放 | 仅在目标岗位需要时开展；不接真实交易 |
| W48-52 | 求职冲刺与项目收敛 | 定向面试、作品修复、年度复盘 | 以 offer/面试漏斗和明确下一阶段策略衡量 |

若 Agent 不满足前置门槛或目标岗位不需要，则 W40-42 回流到数据工程、研究方法或求职；模拟执行最多可扩到 6 周，但全年扩展总预算仍不得超过 10%。

## 全年持续训练

- 每周：Python、SQL、Linux、Git、单元测试、调试和英文技术文档。
- 每两周：数据库/数据建模、数据结构与基础算法、概率统计题。
- 每月：简历项目 bullet、3/10 分钟项目讲解和一轮技术模拟面试。
- W10 起持续维护目标公司/JD 清单、技能差距和投递漏斗，不等待“全部学完”。

## Phase 过渡评审

进入选修或新项目之前，核查官方文档、依赖维护状态、数据授权和适用规则，并记录日期与决定。环境扫描只影响工具选择，不得推翻统计、时间顺序、测试和样本外等基础门槛。
