# Bohr 项目治理规则

## 目的

让学习进度可追踪、学习成果可验证、计划变更可回溯；避免 README 快照、待提交文件与打卡记录彼此漂移。

## 四类事实源

| 维度 | 权威位置 | 更新时机 | 不承担的职责 |
| --- | --- | --- | --- |
| 学习范围与验收 | `curriculum/plans/` | 变更任务前 | 不声明学习已完成 |
| 经验证能力 | `curriculum/plans/JOB_CAPABILITY_MATRIX.md` | 独立实现、测试和口述验收后 | 不记录逐日流水 |
| 历史学习记录 | `Learning_Log.md` | 保留既有确认和复习过程 | 打卡不等于掌握 |
| 代码、测试、报告和求职反馈 | `Learning_Vault/`、`experiments/`、`project/tests/`、验收记录 | 学习与求职过程 | 文件存在不自动提升能力等级 |

根目录的 `README.md` 只说明项目定位和入口，不记录会过时的完成天数。`20/28 Days` 等历史统计只能出现在历史记录或派生审计中，并明确“非掌握证明”。

## 日常闭环

1. 从 `NEXT_12_WEEKS.md` 读取本周目标岗位能力、输入、实践、交付物和退出门槛。
2. 复制周验收模板，先记录独立实现边界和 AI 参与方式。
3. 在教学、可复用模块或正式研究的正确目录中产出代码；记录数据和环境前置条件。
4. 运行正常、边界、非法输入和金融时间顺序测试；失败必须使进程非零。
5. 由学习者完成脱稿口述。只有独立实现、测试通过、能解释同时满足时才更新能力矩阵为掌握。
6. 运行历史证据审计、课程审计和测试；不自动提交 Git。

## 偏差处理

| 情况 | 处理方式 |
| --- | --- |
| 有代码但未打卡 | 标为“待学习者确认”，不自动勾选 TODO 或日志 |
| 日志完成但没有代码 | 暂停推进，补回产物或记录其替代证据 |
| TODO 与日志不同 | 明确记录变更原因；先更新计划，再更新日志 |
| 新增计划外练习 | 放入 `Practice1/` 或对应练习目录，不作为正式完成证据 |
| AI 已生成完整答案 | 标为参考实现；学习者需从骨架独立复现后再验收 |
| 测试通过但无法解释 | 保留 L4 证据，不标记掌握 |
| 能解释但实现/测试失败 | 记录薄弱点并补救，不按日历推进 |
| 求职反馈与自评冲突 | 以可追踪的简历通过率、笔试和面试反馈调整计划 |

## 自动审计

```powershell
python project/scripts/project_audit.py
python project/scripts/curriculum_audit.py
python project/scripts/project_audit.py --write-report
```

历史审计只读取旧计划、历史日志和学习产物；课程审计检查新路线的必备字段。派生报告不修改学习进度或能力矩阵。

## Agent Skill 维护

仓库已追踪的 `.agent/skills/` 是版本控制中的技能源。`.agents/` 与 `.claude/` 是本地客户端副本；在修改工作流时，应先选择一个源文件更新并显式同步，不能假设多个副本天然一致。
